# План реализации v1: веб-приложение владельца кофеен Дринкит

Одна страница на iPhone: выручка своих кофеен с процентами изменений, кто требует внимания, как разгоняются новые точки, кривая «как идёт день против вчера» и табло мотивации по каждой точке. Без своего бэкенда, только публичные данные.

Дата: 20.09.2026. Проверенные источники и примеры ответов: [API-NOTES.md](API-NOTES.md). Кофейни с идентификаторами: [units.json](units.json). Прототипы табло: [prototype/](prototype/). Полная версия на Dodo IS API отложена, её конспект в разделе 8.

## 1. Экраны

### 1.1 «Сводка»: всё ли в порядке за 10 секунд

Сумма «сейчас» по всем точкам с процентом к тому же дню недели неделю назад к этому же часу и вторым числом к вчера к этому часу; сумма за вчера абсолютом с заказами и средним чеком; четыре строки статуса: внимание, присмотреться, разгон, в норме. Внизу таб-панель из четырёх вкладок.

Почему именно так: публичный API отдаёт `weekBefore` как «сегодня минус 7 дней», то есть тот же день недели, что сегодня (проверено по сумме заказов сети, см. API-NOTES). Поэтому «сейчас к тому же дню недели неделю назад к этому часу» считается напрямую из одного ответа и это самое честное сравнение для кофейни с недельным ритмом.

### 1.2 «Точки»: кому нужно внимание

Карточки отсортированы: сначала красные и жёлтые, затем по выручке за вчера. В карточке: имя и алиас, вчера с чеком, сейчас с процентом, заказы, метка возраста для молодых точек. По тапу детали: график по дням за 14 и 28 дней из истории сборщика, таблица последних четырёх недель, кнопка «Табло этой точки», кнопка «Скрыть».

Правила «нужно внимание», значения по умолчанию в конфиге:

| Сигнал | Условие | Цвет |
|---|---|---|
| Точка не торгует | Прошло больше 60 минут после открытия по графику, выручка сегодня 0 | Красный |
| Провал сейчас | Сегодня к тому же дню недели неделю назад к этому часу ≤ −25 %, прошло ≥ 3 часов с открытия, в базе ≥ 15 заказов | Жёлтый |
| Молодая точка | Возраст меньше 8 недель: сигнал только при двух неделях снижения подряд по истории | Жёлтый |

Проценты: «сейчас» показывается только после часа открытия точки по её графику, до этого подпись «откроется в …»; процент серый и без стрелки при базе меньше 20 заказов или возрасте точки меньше двух недель.

### 1.3 «Разгон»: новые открытия

Точки младше 26 недель на одном графике, выровненные по номеру недели с открытия, чтобы 10-9 на своей шестой неделе сравнивалась с 10-3 и 10-8 на их шестой. Под графиком таблица: возраст, средняя дневная выручка за последнюю неделю, изменение к предыдущей неделе.

История копится сборщиком с первого дня его запуска, поэтому сборщик включается на первом шаге работ. Прошлое публичный API не отдаёт.

### 1.4 «Табло»

- **Обзор.** Мини-табло каждой точки: фрейм 820 на 960 пикселей в десктопной раскладке, уменьшенный под ширину телефона. Видны время обслуживания за час, сравнение со вчера, нормативы в процентах и полоса «медленно / нормально / быстро» с цифрами. Проверено на трёх точках, прототип [prototype/board-overview.html](prototype/board-overview.html).
- **Одна точка.** Оригинальное табло на весь экран, переключение точек свайпом или списком сверху.

Табло встраивается фреймом с официального адреса, данные из него не вытаскиваются.

### 1.5 Добавление кофеен по кнопке

Кнопка открывает список точек подразделения «Москва 10» из публичного API, которых ещё нет на экране, плюс поиск по названию по всей Москве. Тап добавляет точку с автоматическим подбором id, UUID для табло, графика работы и даты открытия. Без бэкенда список хранится в браузере телефона, а для партнёров есть кнопка «Поделиться»: ссылка, в которой зашит список точек. Сборщик при этом собирает историю сразу по всему подразделению, поэтому у новой точки «Москва 10» история есть с момента её появления в API, а не с момента нажатия кнопки.

## 2. Данные без бэкенда

Что отдаёт публичный API по каждой точке: `today`, `yesterday`, `yesterdayToThisTime`, `weekBefore` (сегодня минус 7 дней), `weekBeforeToThisTime`, всё накопительно на момент запроса. Живые цифры телефон берёт из него напрямую при открытии и каждые 5 минут.

История нужна только для «Разгона» и графиков по дням. Её копит сборщик без сервера: задача GitHub Actions раз в сутки в 03:40 по Москве опрашивает публичный API по всем точкам подразделения «Москва 10» (их в API уже 15, включая ещё не открытые) и дописывает в `app/public/data/daily.json` два дня из каждого ответа: «вчера» и «сегодня минус 7». Уже первый запуск даёт два дня истории, через неделю история сплошная. Файл лежит в репозитории рядом с сайтом, каждая запись это коммит, резервная копия получается сама. Сборщик запущен вручную 20.09.2026, в файле есть 13.09 и 19.09 по всем точкам подразделения.

Что не хранится и не считается: кривая дня и сравнение «вчера к тому же дню недели», оба убраны по решению владельца.

Определение выручки: поле `revenue` публичного API сверяется с отчётом Dodo IS за один день по каждой точке до запуска. Если совпало, вопрос закрыт. Если расходится на постоянный коэффициент, пишем его в настройках и подписываем на экране. Если расходится непредсказуемо, честно пишем об этом и точные цифры переносим в v2.

## 3. Архитектура и хостинг

```
iPhone (Safari, PWA, установлена на экран «Домой»)
 ├─ живые цифры ────► publicapi.drinkit.dodois.io   (напрямую, CORS открыт)
 ├─ табло ──────────► motivationboard.drinkit.dodois.io (iframe)
 └─ история, кривые ► статические JSON рядом с сайтом
                        ▲
                        │ коммит каждые 30 минут
                  GitHub Actions (сборщик без сервера)
                        │ опрашивает
                        ▼
                  publicapi.drinkit.dodois.io
```

Хостинг по умолчанию: репозиторий на GitHub, сайт на GitHub Pages по адресу вида `имя.github.io/drinkit`, сборщик в том же репозитории. Стоимость ноль. Данные и так публичные, поэтому публичный репозиторий не раскрывает ничего нового; если код хочется держать закрытым, сайт переезжает на Cloudflare Pages с бесплатным адресом `*.pages.dev`, сборщик остаётся в GitHub Actions. Свой домен подключается позже одной записью DNS без изменения кода.

Стек: PWA на React + TypeScript + Vite + Tailwind, компоненты на базе shadcn/ui, адаптированные из референсов 21st (раздел 4), графики на лёгкой библиотеке; сборщик на Python или Node внутри GitHub Actions.

## 6. Автономная работа

- Серверов нет, паролей нет, токенов нет. Единственная регулярная работа: сборщик в GitHub Actions. При сбое GitHub сам присылает письмо владельцу репозитория; в приложении на карточках появляется подпись «данные сборщика устарели» с временем последнего замера.
- Сборщик обрабатывает всё подразделение «Москва 10», поэтому новые точки попадают в историю автоматически. Точки из других подразделений, добавленные через поиск, показываются с живыми цифрами, а история для них появляется после добавления в конфиг сборщика.
- История лежит в git, резервная копия это сам репозиторий.
- Раз в квартал: проверка, что табло открывается во фрейме, и просмотр релиз‑нот Dodo IS.
- Расходы: ноль на бесплатных тарифах. GitHub Actions в публичном репозитории без лимита, в приватном около 1000 минут в месяц из бесплатных 2000.

## 7. Риски v1

| Риск | Что делаю |
|---|---|
| Выручка публичного API расходится с отчётами Dodo IS | Сверка на шаге 8, коэффициент или пометка |
| Задержки запусков GitHub Actions | Замер хранится с реальным временем, кривая рисуется по факту, а не по расписанию |
| Публичный API или фреймы табло закроют | Живые цифры переезжают на Dodo IS API (раздел 8), табло заменяется сборкой из официальных методов без «медленно / нормально / быстро» |
| Список точек хранится в браузере | Ссылка «Поделиться» и дефолтный список в репозитории |
| Семь фреймов табло нагружают телефон | Ленивая загрузка, выгрузка фреймов вне экрана |
| Данные видны всем, у кого есть ссылка | Владелец предупреждён, это осознанное решение |
